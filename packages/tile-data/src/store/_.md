

# Collection hook family

Coordinated hooks over one collection held by the shared store, in `tile-data/src/store/`: a common hook defines the
target and the shared criteria, lens hooks add their own projections on top. Widgets (tile-lens) come later.

## Common collection

`useCollection({ entry, shape, field?, scope?, sieve?, onChange? })` returns the shared `Collection` (plain core
state adopted with `useModel`), passed explicitly to every lens hook (`useOptions(courses, "university")`).

- **target** — `entry`, `shape` and the collecting `field` (blue's name for a member key, `Identifier`-typed, as
	`Property` names blue's member declaration type); lens models describe item values only
	(`{ label: {} }`, not `{ members: { label: {} } }`)
- **field inference** — local helper in `collection.core.ts` (metreeca/blue#36 closed as not planned: each
	consumer needs its own rule, and the duplication is a few lines per site). `useCollection` defaults `field` only
	where unambiguous, throwing `TypeError` when `field` is omitted and the shape lists none (`missing collection
  field`) or several (`ambiguous collection field [a, b]`, naming the candidates so the caller can pick one); at the
	type level, `Collections<S>` / `Sole<S>` make omitting it a compile error unless the shape holds exactly one

	candidates, as specified in #36: multi-valued (`range.maxCount !== 1`) `"property"` members of
	`getShapeProperties(shape)` ranging over resources (every branch of `getShapeBranches(range.shape)` reaching one
	through `getShapeTarget`), in declaration order, inherited members included, reverse/`foreign`/`captive` ones not
	filtered out; an explicit `field` is not checked against the list at runtime, so a caller may bind any collection blue's
	`collection(shape, slice)` resolves
- **scope** — fixed criteria bounding the screen (e.g. courses of one university): joined to every retrieval,
	baselines included; never written by lenses, never cleared, never persisted
- **sieve** — the reader's criteria, as qest `Criteria`, narrowing keys only: `<` `>` `<=` `>=` `~` `?` `!`;
	`filter(criteria)` merges keys (`undefined` removes), `clear()` empties; `^` (order) and `+` (focus) rejected with
	`TypeError`, as they belong to views
- **seed** — `sieve` option read at creation only; `onChange(sieve)` called after every reader change (`filter`,
	`clear`), never at creation, so the screen can persist the criteria wherever it likes (see *URL sync*)

## Lens hooks

Each takes the collection and writes only its own criteria keys through `filter`. Retrieving hooks return a `Relay`
over `blank` / `ready` / `error` (`<Noun>Cases`); write transitions on `ready` only; `ready` stays on show while new
criteria are retrieved; `reload()` on `error`.

| Hook          | Retrieves                                                  | Own keys / view state                                   |
|---------------|------------------------------------------------------------|---------------------------------------------------------|
| `useMembers`  | first items under `model` (checked by `Admitted`), `#`     | none; `order`, `limit` (`members.core`): `load?()`, `sort()` |
| `useCount`    | `count=count:` under scope + sieve                         | none                                                    |
| `useKeywords` | nothing (plain object)                                     | `~expr`; typed `text`, debounced `search()`, `commit()` |
| `useRange`    | `min=` / `max=` under scope + sieve, own bounds included   | `>=expr`, `<=expr`; `narrow({ lower?, upper? })`, `clear()` |
| `useOptions`  | baseline (scope) + matching (sieve minus own key)          | `?expr`; keywords, offset, limit (`options.core`)       |
| `useActions`  | nothing: `create()` / `delete()` on the items              | none                                                    |

- **members** — growing window: `load?()` offered while the last batch was full, ignored while a batch is on its way,
	so `{members({ ready: ({ load }) => load && <More onLoad={load}/> })}` wires progressive loading; `Sheet` takes the
	members relay and renders items only, the screen closes it with `More`; order is view state (`sort()` restarts from
	the first batch), so several tables over one collection keep their own
- **options** — legacy behaviour: `value=expr` (atomic: literal or IRI, as written to `?expr`), optional
	`frame=expr` under a caller `model`, `count=count:`, `^count: -2`, `+expr` focus on selected values, `~text`
	keywords (`text` defaults to `expr`), `@` offset, `#` limit + 1 for `more`; merge selected-matching,
	selected-baseline (count 0), matching, baseline (count 0); no hardwired properties (no `label`)
- **typing** — expressions are plain qest `Expression`s, values plain qest values (`Literal`, `Option`): no
	`encode`/`decode`, formatting and parsing belong to views; shape-driven expression typing deferred
- **presentation state** (option keywords and page, members order and limit, uncommitted keywords) lives in each
	lens, never in the collection; keywords follow the sieve as it changes elsewhere

## URL sync

Goal: catalogue pages keep the reader's criteria across reloads and navigation, replicated on every catalogue, so the
wiring must stay a one-liner; `useCollection` and `useQuery` know nothing of each other and meet at the call site:

```tsx
const [query, setQuery] = useQuery();

const courses = useCollection({ entry: "/courses/", shape: Course, sieve: query, onChange: setQuery });
```

- **`useQuery()`** (`tile-data/src/store/query.ts`, qest-aware, re-exported from `store/index.ts`), ported from legacy `_/data/hooks/query.ts`: `[criteria, setCriteria]`
	as qest `Criteria` (`encodeCriteria` / `decodeCriteria`); read once at mount from the URL query, then
	`sessionStorage[<route>#query]` (sticky filters across plain links, as in ec2u); `setCriteria` writes both through
	`history.replaceState`, leaving the entry state alone, and renders again; knows nothing of collections;
	`history.state` dropped as redundant with the entry's own query
- **no outside-change plumbing** — the router remounts the page on navigation, so the criteria are read back at
	mount: back to a catalogue restores its history entry state, a fresh link restores the session's last criteria;
	filter steps use `replaceState`, so they never create history entries and `popstate` needs no handling; no
	`useModel` source, no `restore` transition, no `Persistence` backends
- **router fix** — today `Router` tracks `location.pathname` only, so a link changing just the query neither renders
	nor remounts: the router records path + query at each navigation it handles (`navigate`, link clicks, `popstate`)
	and `Routes` keys the routed view by it; `replaceState` writes from `useQuery` bypass the router and never remount;
	`useRoute()` keeps returning the path alone
- `scope` never reaches the URL: `onChange` hands over the sieve alone

## Store

- default `Store` factory: `createCachingStore(createRESTStore({ fetch }))`; options baselines depend on `scope` only
	and are served from cache after the first lookup
- fan-out accepted (N facets + window + count per criteria change, concurrent); coalescing is a gate-side concern
	(multi-query endpoint over keep batching), transparent to tile-data

## Layout

One module per hook under `tile-data/src/store/`, headless core beside it (no Preact, tested without a DOM); `_` prefix
dropped as each module is ported and tested.

All re-exported from `store/index.ts`.

| Module          | Hook            | Core                                                          |
|-----------------|-----------------|---------------------------------------------------------------|
| `collection.ts` | `useCollection` | `collection.core.ts`: target, scope, sieve, `filter`, `clear` |
| `members.ts`    | `useMembers`    | `members.core.ts`: order, limit, `load`, `sort`               |
| `count.ts`      | `useCount`      | none                                                          |
| `keywords.ts`   | `useKeywords`   | none                                                          |
| `range.ts`      | `useRange`      | none                                                          |
| `options.ts`    | `useOptions`    | `options.core.ts`: keywords, offset, limit                    |
| `actions.ts`    | `useActions`    | none                                                          |
| `index.core.ts` | `useEntry`      | shared store binding, models compared by content              |

## Widgets

`tile-lens` widgets over the collection hooks, ported from the legacy `_/lens/lenses` (and `_/cell/search.tsx`); each
renders a `<tile-*>` element with its sibling stylesheet, takes the collection (or the relay a screen already holds,
as `Sheet` takes the members relay), and leaves layout and progressive loading to the screen.

| Legacy                 | Hook                 | Widget                                                                  |
|------------------------|----------------------|-------------------------------------------------------------------------|
| `count.tsx`            | `useCount`           | count label: "no items" / "1 item" / "12 items", "matches" while sieved |
| `clear.tsx`            | `collection.clear()` | clear-filters button, disabled while the sieve is empty                 |
| `_/cell/search.tsx`    | `useKeywords`        | keyword search box: typed text, debounced search, commit on Enter       |
| `options.tsx`          | `useOptions`         | facet: searchable checklist with counts, paging, selected on top        |
| `range.tsx`            | `useRange`           | range facet: lower / upper inputs, min / max as hints                   |
| `table.tsx`            | `useMembers`         | table view beside `Sheet`, with sortable columns through `sort()`       |

Order, smallest first, so the hooks are exercised end to end in the specimen before the heavier facets:

1. count and clear
2. search box
3. options facet
4. range facet
5. table

Each widget test-first, a11y contract (roles, keys, focus) settled before rendering, a specimen section per widget,
committed on its own.
